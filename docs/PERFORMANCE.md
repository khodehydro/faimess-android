# پاسخ‌گویی به لمس — نسخهٔ 0.1.1

هدف این مرحله کاهش کار غیرضروری هنگام لمس است؛ ظاهر، ابعاد دکمه‌ها و رفتار معمول کلیک/اسکرول حفظ شده‌اند. هنوز روی گوشی کاربر benchmark قبل/بعد ثبت نشده، بنابراین درصد افزایش سرعت یا عدد FPS ادعا نمی‌شود.

## تغییرات اجرایی

- **تصاویر آفلاین غیرهم‌زمان:** همهٔ عکس‌ها و آواتارها در زمان اجرای اپ با Coil 2.7.0 بارگذاری می‌شوند، نه با decode هم‌زمان `painterResource` روی رشتهٔ رابط کاربری. آیکون‌های برداری کوچک و Preview اندروید استودیو همچنان از منابع معمول استفاده می‌کنند.
- **کش مشترک و محدود حافظه:** همان تصویر محلی در فید، گرید، استوری و sheet استفاده می‌شود. منابع تصویری از قبل حداکثر ۱۲۰۰ پیکسل و آواتارها ۱۹۲ پیکسل هستند؛ درخواست اندازهٔ اصلی مانع ساخت نسخهٔ جداگانه برای هر محل نمایش می‌شود. دو تصویر منظره پس از اولین فریم به‌صورت غیرهم‌زمان پیش‌بارگذاری می‌شوند. crossfade و disk cache اضافی فعال نشده‌اند؛ اینترنت در زمان اجرا لازم نیست.
- **callbackهای پایدار:** هندلرهای پست با `remember` نگهداری می‌شوند و شناسهٔ پست را می‌گیرند، نه snapshot قدیمی لایک و کامنت. اشتراک‌گذاری، محتوای فعلی را از ViewModel می‌خواند.
- **رندر محدودتر کارت:** هدر، متن و رسانه فقط داده‌های موردنیاز خود را دریافت می‌کنند تا تغییر شمارنده‌ها آن‌ها را بی‌دلیل بازترکیب نکند. فقط مدل‌های واقعاً تغییرناپذیر علامت `Immutable` دارند؛ `List`های عمومی به‌اشتباه immutable اعلام نشده‌اند.
- **بازخورد کوتاه‌تر:** تغییر رنگ تب ۹۰ میلی‌ثانیه و باز/بسته شدن متن ۱۲۰ میلی‌ثانیه است، با رعایت مقیاس انیمیشن سیستم. انتخاب تب و تغییر لایک منتظر تمام شدن انیمیشن نمی‌مانند.
- **پیام تازه، بدون صف قدیمی:** پیام عملیات اخیر جای پیام قبلی را می‌گیرد؛ پیام‌های ذخیره/حذف ذخیره پشت سر هم چند ثانیه منتظر نمی‌مانند. این رفتار فقط پیام‌ها را ادغام می‌کند، نه خود لمس‌ها را.
- **انتشار مستقیم در بالای فید:** پس از انتشار، به‌جای انیمیشن طولانی اسکرول، پست جدید فوراً در بالای فید نمایش داده می‌شود.
- **کیبورد و فهرست‌ها:** نمایش/پنهان‌سازی نوار پایین فقط به تغییر وضعیت باز بودن کیبورد واکنش می‌دهد، نه هر پیکسل انیمیشن آن. نتایج فیلتر و جستجو برای ورودی ثابت حفظ می‌شوند.

هیچ تأخیر مصنوعی، debounce عمومی، اجرای عملیات روی touch-down یا تغییر تنظیمات لمس سیستم اضافه نشده است. لمسِ لغوشده با اسکرول نباید به کلیک ناخواسته تبدیل شود.

## نصب نسخهٔ بهینه برای بررسی روی گوشی

Build دیباگ برای توسعه مناسب است، نه قضاوت نهایی دربارهٔ کارایی Compose. یک build type اختیاری به نام `performance` اضافه شده که بهینه‌سازی R8 و resource shrinking نسخهٔ release را دارد، debuggable نیست و برای نصب محلی با **کلید debug همان سیستم** امضا می‌شود. این خروجی برای فروشگاه نیست.

در ترمینال پروژه، با گوشی یا امولاتور متصل:

```powershell
git pull --ff-only origin arena/4ab96fac-faimess-android
.\gradlew.bat :app:installPerformance
```

سپس اپ **FAIMESS** را از دستگاه باز کنید. App ID همان قبلی است؛ اگر نسخهٔ نصب‌شده را با همان debug key ساخته باشید، نیازی به حذف اپ نیست. اگر کلید امضای نسخهٔ قبلی متفاوت است، آن را بی‌اطلاع حذف نکنید؛ ابتدا از داده‌های مهم نسخهٔ قبلی محافظت کنید.

APK ساخته‌شده:

```text
app/build/outputs/apk/performance/app-performance.apk
```

اجرای معمول Android Studio همچنان می‌تواند variant دیباگ را نصب کند. برای مقایسهٔ واقعی، هر بار variant یکسان را روی دستگاه یکسان و بدون debugger بررسی کنید. Build اول نسخهٔ performance ممکن است به‌دلیل R8 بیشتر طول بکشد؛ زمان ساخت با سرعت اجرای اپ فرق دارد.

## چک‌لیست مقایسه

1. یک بار با اپ تازه‌بازشده و یک بار پس از گرم شدن کش تست کنید.
2. روی لایک هفت بار سریع لمس کنید؛ وضعیت نهایی باید دقیقاً مطابق هفت عمل تغییر کند.
3. Home / Discover / Profile / Search را پشت سر هم عوض کنید؛ تب نهایی و دادهٔ پست‌ها باید درست بمانند.
4. استوری و پیش‌نمایش تصویر را چند بار باز و بسته کنید.
5. یک پست را چند بار ذخیره/حذف ذخیره کنید؛ پیام قدیمی نباید با تأخیر طولانی ظاهر شود.
6. با کشیدن انگشت برای اسکرول، کلیک ناخواسته نباید ثبت شود. TalkBack و دکمهٔ Back هم باید همان رفتار قبلی را داشته باشند.
7. در صورت باقی ماندن کندی، مدل دستگاه، نسخهٔ Android، نوع build و عملیات مشخص را گزارش کنید. برای اندازه‌گیری، در Perfetto/System Trace ورودی و فریم‌های همان عملیات را ثبت کنید؛ از یک عدد تجربی یا تست عملکردی نمی‌توان FPS نتیجه گرفت.

## بررسی‌های خودکار

- تست واحد لمس‌های متوالی، بازیابی state و ثابت ماندن داده‌های پست‌های دیگر.
- تست واحد جایگزینی آخرین Snackbar و لغو آن با پایان عمر UI.
- تست Compose لمس‌های سریع و حفظ آخرین وضعیت هنگام جابه‌جایی صفحه.
- تست دستگاه برای استفادهٔ مجدد تصویر از memory cache.
- Screenshot منتظر آماده شدن عکس‌های غیرهم‌زمان می‌ماند؛ خروجی تست در پوشهٔ Downloads امولاتور ذخیره می‌شود تا پاک‌سازی APK توسط تست‌رانر آن را حذف نکند.
- CI هر دو APK دیباگ و performance را می‌سازد. نتیجهٔ واقعی اجرای CI جدا از این فهرست امکانات ثبت می‌شود.
