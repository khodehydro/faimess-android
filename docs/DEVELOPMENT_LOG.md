## ۲۰۲۶-۱۰-۱۴ — مرحلهٔ اول: بازسازی رابط مرجع

### درخواست

ساخت نسخهٔ اولیهٔ اندروید با Kotlin و Jetpack Compose بر اساس تصویر Frindle؛ نگه داشتن طراحی اولیه برای اصلاحات مرحله‌ای بعد؛ ثبت و پوش تغییرات و آماده کردن دستور دریافت مستقیم در Android Studio.

### وضعیت شروع

- ریپازیتوری: `khodehydro/faimess-android`
- کامیت مبنا: `131ee754ed8ef7cea528d22e08ca36d2a08292b7`
- محتوای اولیه: فقط README؛ پروژهٔ Android وجود نداشت.
- شاخهٔ کار: `arena/ce2383fc-faimess-android`

### نتیجهٔ این مرحله

- پروژهٔ کامل Android از پایه ایجاد شد.
- رابط اصلی و تعامل‌های آفلاین نمونه پیاده شد.
- تصاویر مشابه محلی، فونت و آیکون‌ها داخل پروژه قرار گرفتند.
- مسئولیت‌های مدل، داده، ViewModel، صفحه‌ها، کامپوننت‌ها و تم جدا شدند.
- تست واحد، تست Compose، ثبت screenshot و گردش‌کار CI اضافه شد.
- راهنمای فارسی کلون/باز کردن/اجرای پروژه، راهنمای معماری، منشأ فایل‌ها و Changelog اضافه شد.
- جزئیات تغییرات در [CHANGELOG](../CHANGELOG.md) و محدودیت‌ها در README آمده است.

### بررسی

بررسی استاتیک فایل‌ها و منابع در محیط توسعه انجام می‌شود. محیط توسعه Java و Android SDK ندارد؛ نتیجهٔ build، lint و اجرای تست روی دستگاه باید از اجرای واقعی [Android CI](https://github.com/khodehydro/faimess-android/actions/workflows/android.yml) خوانده شود. ثبت نتیجهٔ مشاهده‌شدهٔ CI در ادامهٔ همین گزارش انجام خواهد شد؛ صرف اضافه شدن فایل workflow به معنی موفقیت تست‌ها نیست.

### اصلاح سازگاری Android 8.0

اجرای [38544413946](https://github.com/khodehydro/faimess-android/actions/runs/38544413946) تا Android Lint پیش رفت و یک خطای API برای `windowLightNavigationBar` در تم پایهٔ API 26 گزارش کرد. تنظیم XML که به API 27 نیاز داشت حذف شد؛ مدیریت آیکون‌های سیستم به `enableEdgeToEdge` سپرده شد و برای API 26 پس‌زمینهٔ تیرهٔ خوانا در نظر گرفته شد. خطا با تغییر واقعی کد رفع شد، نه با خاموش کردن lint یا افزایش حداقل نسخهٔ اندروید.


## ۲۰۲۶-۱۰-۱۴ — میرورهای مایکت برای Gradle Sync

طبق درخواست کاربر پس از خطای دانلود پلاگین در Android Studio، مایکت در هر دو فهرست مخزن پلاگین و کتابخانه در اولویت قرار گرفت. Wrapper نیز به مسیر رسمیِ مستندشدهٔ مایکت برای Gradle 8.11.1 منتقل شد؛ SHA-256 منتشرشده توسط Gradle برای همان ZIP ثبت شد. نسخه‌ها و کد اپ بدون تغییر ماندند.

- دریافت POM مربوط به plugin markerهای AGP 8.9.2، Kotlin Android 2.1.20 و Compose Compiler 2.1.20 از مایکت بررسی شد.
- ترتیب مخزن‌ها، نسخه و checksum Wrapper و پاکیزگی diff بررسی شد.
- محیط محلی Java و Android SDK ندارد؛ build کامل این تنظیمات از طریق میرور در این محیط اجرا نشده و موفقیت آن ادعا نمی‌شود.
- راهنمای دریافت تغییرات و Sync در `docs/MYKET_MIRROR.md` ثبت شد.
- برای تفکیک وضعیت قبلی: در اجرای CI شمارهٔ `38545021314`، مرحلهٔ build / unit tests / lint و تولید APK موفق بود، ولی job تست رابط روی امولاتور ناموفق شد؛ این اجرا مربوط به تنظیمات پیش از مایکت است و تأیید build میرور یا موفقیت همهٔ تست‌ها نیست.


## ۲۰۲۶-۱۰-۱۴ — پاسخ‌گویی سریع‌تر به لمس (0.1.1)

کاربر اجرای موفق `assembleDebug` و نصب اپ را تأیید کرد و سپس کاهش کندی دکمه‌ها و عملیات را خواست. در بررسی کد، بارگذاری هم‌زمان عکس‌ها با `painterResource`، ساخته شدن دوبارهٔ مجموعهٔ callbackها و صف پیام‌های Snackbar مسیرهای قابل بهبود بودند.

بارگذاری عکس‌ها به Coil با منابع محلی و کش مشترک منتقل شد؛ callbackها بر اساس شناسه پایدار شدند؛ داده‌های هدر/رسانه از شمارنده‌های تعامل جدا شد؛ انیمیشن‌های کوچک کوتاه‌تر، نمایش پست منتشرشده مستقیم و پیام‌ها latest-only شدند. نسخهٔ اختیاری `performance` و تست‌های رگرسیون اضافه شدند. ظاهر و رفتار استاندارد کلیک، لغو لمس هنگام اسکرول، دسترس‌پذیری و حالت آفلاین حفظ شده‌اند.

در این محیط Java/SDK و گوشی کاربر در دسترس نیست؛ زمان لمس یا FPS قبل/بعد اندازه‌گیری نشده است. بررسی استاتیک و اجرای CI وضعیت جداگانه دارند و صرف وجود تست به معنی موفقیت آن نیست. دستور نصب محلی و روش بررسی در `docs/PERFORMANCE.md` ثبت شده است.


## ۲۰۲۶-۱۰-۱۴ — برند FAIMESS: رنگ، نام و لوگو از وب‌اپ (0.2.0)

کاربر مشخص کرد پروژهٔ اصلی، سایت استریم موسیقی FAIMESS (`khodehydro/faimess-doc`، شاخهٔ `arena/01a10c49-faimess-doc`) است و خواست رنگ، نام و لوگوی اپ اندروید از همان سایت گرفته شود.

- **منبع:** `src/assets/brand/faimess-logo.png` (گربهٔ سفید روی بنفش، ۱۵۰×۱۵۰)، توکن‌های `@theme` در `src/index.css` و `docs/design-tokens.json`، و نحوهٔ نمایش لوگو/واژه‌نشان در `src/ui/Logo.tsx` و اسپلش در `src/ui/Splash.tsx`.
- **لوگو:** فایل اصلی بدون تغییر به `res/drawable-nodpi/brand_logo.png` منتقل شد. آیکون لانچر با همان روش اسکریپت `tools/appicons.py` سایت (میدان پوشش + سوپرسمپل) ولی به‌صورت لایهٔ جلوی شفاف برای adaptive icon ساخته شد: `tools/brand_assets.py`. دورترین نقطهٔ گربه ۳۲٫۷dp از مرکز است، داخل ناحیهٔ امن ۳۳dp.
- **رنگ:** `Color.kt` با نام‌های همان سایت بازنویسی شد؛ نگاشت قدیمی→جدید: Lime→Primary، Ink→Ink جدید، MutedInk→InkMuted، FeedBackground→Canvas، SoftSurface→Subtle، Leaf→PrimaryDeep، HeartRed→Heart (rose سایت) و خطاها→FlameDeep.
- **نام:** `app_name`، تم‌ها، کلاس‌ها، تست UI و اسکریپت CI.
- **بررسی:** PNGهای تولیدشده با رمزگشایی مستقل بررسی و پیش‌نمایش ترکیب‌شده روی بنفش با ماسک دایره دیده شد. محیط Java/SDK ندارد؛ نتیجهٔ build و lint باید از CI همین شاخه (`arena/4ab96fac-faimess-android`) خوانده شود.
- **اصلاح CI موروثی:** اجرای CI همین شاخه (`38569013341`) نشان داد اپ، تست‌های واحد و `assembleDebug` موفق‌اند ولی `compileDebugAndroidTestKotlin` به‌خاطر import نامعتبر `androidx.compose.ui.test.onAllNodes` (که از نسخهٔ 0.1.1 مانده بود و در اجرای `38565371823` شاخهٔ قبلی هم با همان خطا شکست خورده بود) خطا می‌دهد. `onAllNodes` عضو خودِ `ComposeTestRule` است و import لازم ندارد؛ خط import حذف شد.
- **اولین اجرای واقعی تست‌های دستگاه:** پس از رفع import، اجرای [38570006907](https://github.com/khodehydro/faimess-android/actions/runs/38570006907) در job اول (کامپایل، تست واحد، lint، هر دو APK) موفق شد و برای نخستین بار ۱۳ تست Compose روی امولاتور API 35 اجرا شدند: ۱۱ تست گذشتند (از جمله `onNodeWithText("FAIMESS")`، ناوبری، لایک، استوری، کامنت، جستجو) و دو تست موروثی شکست خوردند که هیچ‌کدام به برند مربوط نبود:
  - `OfflinePhotoTest`: `expected:<MEMORY_CACHE> but was:<DISK>`. علت در منبع Coil 2.7.0 بررسی شد: `BitmapFactoryDecoder.configureScale` برای منبع resource با `Size.ORIGINAL` مقدار `inScaled = true` می‌گذارد و نتیجه `isSampled = true` ثبت می‌شود؛ `MemoryCacheService.isSizeValid` ورودی sampled را برای درخواست ORIGINAL رد می‌کند. یعنی ادعای «یک بار decode، استفادهٔ مشترک» نسخهٔ 0.1.1 روی دستگاه برقرار نبود. درخواست به کادر غیردقیق ۱۲۰۰ پیکسلی تغییر کرد (`OfflinePhoto.kt`).
  - `captureReferenceHomeScreenshot`: `expected:<[saved]> but was:<[]>`. `UiAutomation.executeShellCommand` فرمان را با `Runtime.exec` و بدون shell اجرا می‌کند؛ `&&` و `echo saved` به‌عنوان آرگومان‌های `mkdir` رفته بودند. سه فرمان جداگانه و بررسی اندازهٔ فایل با `stat` جایگزین شد.
- **نتیجهٔ نهایی CI این مرحله:** اجرای [38571947745](https://github.com/khodehydro/faimess-android/actions/runs/38571947745) روی کامیت `cb43150` در هر دو job موفق شد؛ هر ۱۳ تست دستگاه روی امولاتور API 35 گذشتند و برای اولین بار artifact `app-screenshots` (اسکرین‌شات واقعی صفحهٔ خانه با برند FAIMESS) تولید شد. محیط توسعه به حافظهٔ artifact گیت‌هاب دسترسی ندارد؛ تصویر باید از صفحهٔ همان اجرا دانلود و بررسی شود.
